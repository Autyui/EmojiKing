# 本地表情输入法兼容性原型

这是一个 Java 编写的最小 Android 原型，验证三件事：

1. 从系统文件选择器导入一张、多张或一个授权目录中的本地图片。
2. 目标输入框声明支持图片时，通过 `commitContent` 标准接口提交。
3. 目标未声明支持或拒绝标准提交时，向当前应用发起图片分享。

应用内的测试输入框声明支持 `image/*` 并实现了接收端，可先验证输入法、URI
授权和图片读取的完整本地链路。普通 `EditText` 默认不会声明富媒体类型。

## 本地表情库

- 目录数据保存在应用私有的 `files/emoji-library/catalog.json`，当前格式版本为 `2`；旧版嵌套目录会在读取时自动迁移。
- 图片保存在 `files/emoji-library/images/`，目录只记录经过校验的相对路径。
- 表情包是全局独立实体，图库只保存表情包 ID 引用；同一表情包可同时加入多个图库，从一个图库移除不会删除共享内容。
- 首次读取会把旧的 `files/emoji/current.*` 复制到“本地图库 / 默认表情包”，不会删除旧图片；重复启动不会再次迁移。
- 导入新图片时先复制到暂存文件并读取真实图片边界，再写入唯一的托管文件；发送不依赖外部 URI 的长期权限。
- 当前支持 PNG、JPEG、WebP 和 GIF，单文件上限为 20 MiB、解码尺寸上限为 4000 万像素。只要求宽高大于 0，不设置最小像素尺寸；`338 x 267` JPEG 已纳入设备回归测试。
- 首次真实导入会替换内置占位表情并保留系统文档显示名，不再继续显示“默认表情”。后续导入追加到所选表情包。
- 内容完全相同的图片在同一表情包内按 SHA-256 判定为重复；独立表情包之间可以分别导入同一图片，同名但内容不同的图片也不会覆盖。
- 删除表情或删除类只移除目录记录和应用私有的托管副本，不会删除手机相册等外部来源文件；同一图片分别导入多个类时各自独立，删除一个类不会影响其他类中的副本。
- 批量导入逐张提交，有效图片不会因同批其他图片损坏而回滚；完成提示分别显示导入、重复和失败数量。
- 可一次新建多个表情包并关联到多个图库，也可批量把已有表情包加入当前图库。图库和类单击只负责切换，连续双击类才打开管理菜单：可重命名类、删除该类，或在当前类内多选删除表情包；批量删除不会影响其他类，也不会删除类本身。
- 目录导入仅使用系统 `ACTION_OPEN_DOCUMENT_TREE` 授权；Android 6-12 可额外申请共享图片读取权限，Android 13 及以上继续由系统选择器逐项授权。不申请“所有文件访问”，不绕过系统限制读取 `/Android/data` 或其他应用私有目录。
- 目录版本、重复 ID、路径穿越、损坏 JSON、缺图或不支持的 MIME 会明确失败，不会静默变成空图库。
- 主界面和输入法读取同一份目录与选择状态，任意表情网格项都继续复用既有标准提交/分享降级策略。

主界面与输入法面板均按预览图采用“左侧图库栏 + 顶部表情包栏 + 四列表情网格”结构。图库和类单击只负责切换，连续双击类才打开重命名、删除该类或当前类内批量删除表情包的菜单；单个表情点击打开备注/移除/查看菜单，查看详情支持按钮和捏合缩放。云端操作统一放在独立的“云端”页面，包含上传、同步和批量删除。

## 构建

项目使用 Android Gradle Plugin 7.3.1，需要 JDK 11：

```powershell
$env:JAVA_HOME = 'E:\Tools\android\jre'
.\gradlew.bat :app:assembleDebug
```

APK 输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 发送策略

点击输入法中的图片后：

- 当前输入框声明支持图片 MIME 时，先调用标准 `commitContent`。返回 `true` 后立即结束，不再打开分享。
- MIME 不匹配、声明为空或标准提交返回 `false` 时，优先打开当前输入框所属应用的图片分享入口。
- 当前应用不能处理图片分享时，打开系统分享选择器。
- “分享发送”按钮始终手动打开分享，用于目标接受标准提交但没有显示图片的情况。

“标准提交已接受”仅表示目标输入连接接受了调用；“已打开目标应用分享”和“已打开系统分享选择器”仅表示对应界面已启动。这些提示都不代表图片已经发送成功。

## 实机验证

1. 安装并打开 APK。
2. 点击“选择一张或多张图片”，选择 PNG、JPEG、WebP 或 GIF；也可通过“从授权目录导入”选择系统允许访问的目录。
3. 点击“打开系统输入法设置”，启用“本地表情输入法”。
4. 先点击应用内的“本地接收测试”输入框，切换输入法并点击图片；应看到“本地链路通过”和接收预览。
5. 在微信输入框中点击图片；若微信声明支持当前 MIME，应直接提交且不打开分享界面。
6. 打开 QQ 私聊输入框并切换到“本地表情输入法”。
7. 点击图片；当前实测 QQ 未声明富媒体 MIME，应直接打开 QQ 分享确认界面并显示图片预览。
8. 点击“分享发送”，确认可以手动再次打开当前应用分享。

结果判定：

- 微信标准提交被接受后不应同时出现分享界面，避免重复发送。
- QQ 分享界面可能要求重新选择会话或确认发送，这是系统分享的预期边界。
- 目标应用没有图片分享入口时，应出现系统分享选择器或明确的失败提示，不应崩溃。

主界面的“通过系统分享测试图片”是对照入口，可独立检查图片 URI、权限和文件本身是否正常。

## 26 键中文输入

输入法使用固定约 304dp 高度，顶部可在文字键盘和表情图库之间切换。拼音与候选词共用顶部工具栏，候选栏支持横向滑动并最多查询 15 个候选；点击最右侧箭头后，原键盘区域会切换成三列候选面板，再次点击箭头可返回 26 键。文字模式采用三行 QWERTY 共 26 个字母键，字母键共享一块连续底板且没有单键边框；第三行删除键固定在最右侧，并与 `M` 键保留不可点击间隔。点击候选或空格提交，退格优先删除拼音，回车优先执行输入框动作，“中英”切换英文直输。

主界面“设置”中可从系统相册选择键盘背景，也可恢复默认背景。图片经过校验和缩放后复制到应用私有的 `files/keyboard-theme/background.jpg`，不会修改或删除相册源文件，也不会加入 Android 云备份。背景仅用于文字键盘；字母和功能键会自动切换为高对比度样式，表情图库继续使用实色背景。源图上限为 20 MiB、4000 万像素，保存时最长边缩放到 1600 像素。

连续拼音会按音节切分，完整词组优先；完整音节存在时不会额外混入逐字母拆分结果，例如输入 `ru` 只查询 `ru`，不会加入 `r`、`u` 的候选。没有词组命中时，会由单字索引组合兜底候选。更丰富的模糊拼音与联想候选留待后续实现。候选提交后会记录本机使用次数，下一次相同拼音查询时优先显示用户常用候选。内置完整大词库文件 `app/src/main/assets/lexicon_chat.json`，并使用 `common_hanzi.txt` 优先常用单字，来源为 [Gong-Yie/lexicon](https://github.com/Gong-Yie/lexicon) 的 `大词库.json` 和 `EncodeTable/CommonHanzi.txt`；使用或再分发前请核对上游数据许可。

大词库在输入法服务创建时由后台线程流式预热，同一应用进程只解析一次；候选检索也在后台执行，快速连续输入只显示最新一次查询结果。最近 96 次查询保存在内存缓存中，候选使用次数同样从内存读取并异步保存，从而避免按键时反复解析词库、读取本地配置或在主线程扫描候选。首次启动仍需要完成一次词库解析，此时界面会显示“词库加载中”，但字母点击和界面切换不会被解析过程阻塞。

## EmojiKing 云端

设置中的“云端”会打开独立页面。默认地址为 `https://emoji-king-imagehosting.vercel.app/`，可在页面中修改。云端服务需要提供：

- `POST /api/upload`：接收 `machine_code`、`filename`、`content_type` 和 Base64 `data`。
- `GET /api/images?machine_code=设备ID`：返回当前设备的图片 URL 列表。
- `DELETE /api/delete`：接收 `machine_code` 和云端返回的 `path`，仅删除当前设备的云端图片。

同步时会先下载到应用缓存，再按真实图片内容导入本地表情包；本地目录仍是主界面和输入法的唯一读取来源。云端页面只展示当前机器码对应的远端记录，支持多选后顺序删除；删除不影响本地图片。当前云端地址和设备 ID 保存在应用本地，服务端 GitHub 凭据只应配置在服务端。
